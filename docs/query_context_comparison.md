# Query rewriting and transcript context evaluation

The local classifier qualification measures directedness and stop decisions.
This companion experiment measures the downstream work that query synthesis
supports: resolving references, choosing tools, supplying arguments and
producing an answer grounded in tool data or the ambient transcript.

## Run

Use a locally hosted OpenAI-compatible model from the activated Jarvis
development environment. Authentication is supplied through an environment
variable; its value is excluded from reports.

```bash
PYTHONPATH=src:. python -m evals.run_query_context_comparison \
  --base-url http://127.0.0.1:8000/v1 --model YOUR_LOCAL_MODEL \
  --planner-timeout 15 --judge-timeout 20 --repeats 3 \
  --output /tmp/query-context-comparison.json
```

`EVAL_COMPARISON_API_KEY` supplies optional authentication. The CLI accepts
`--fast-model` for a separate rewrite/router model and `--case` for a pilot.
Omitting timeout overrides uses production configuration defaults.
The default request profile sets `chat_template_kwargs.enable_thinking=false`
uniformly, because a reasoning template can consume the router's short output
budget. `--server-thinking` selects the server's default template instead.

## Method

| Arm | Current query | Ambient transcript |
|-----|---------------|--------------------|
| `rewrite` | Generated by the existing full-context intent judge | Available to the judge |
| `raw_only` | Original utterance | Omitted as a diagnostic control |
| `raw_context` | Original utterance | Separate fenced reference data on router, planner and reply requests |

All arms receive the same seeded conversation history. Context includes the
actual judge prompt's current-segment markers, timestamps, wake state and
TTS echo metadata. The candidate context prompt gives current speech priority
and treats earlier instructions as data.

The twelve cases cover explicit requests, ambient references, interleaved
topics, dialogue follow-ups with echo, Spanish and Turkish references, a fact
already spoken, topic switching, unrelated prior instructions and a long
buffer. Each case runs three times with rotating arm order. These are twelve
distinct scenarios, not thirty-six independent samples per arm.

The replay executes the real judge/router/planner/reply code. Tool actions
return controlled fixture data, and each trial uses fresh dialogue memory and
an empty database. Empty diary retrieval is stubbed, so no embedding service
is required. This does not measure web search quality, speech recognition,
memory retrieval or classifier accuracy. Raw arms assume a correct directed
verdict; a classifier still needs separate qualification.

Completion requires the intended tool and referent, expected answer facts,
no unrelated tool action, and valid responses from every model request.
Model errors, empty replies and output truncation count as failures even if
the engine later recovers. Router selection is reported separately.
Request and total latency, token usage and cached tokens are traced.
Missing usage remains unknown.

## Evidence

The local replay uses `Qwen3.8-27B-MTPLX-Optimized-Speed` through oMLX on an
Apple M5 Max, with the same model for FAST and CHAT tiers. Temperature is zero,
reasoning is disabled uniformly, and production output caps are retained.
The exploratory profile allows 15 seconds for planning and 20 seconds for
the intent judge. These results do not establish quality or latency for the
default Gemma FAST-tier model, or the production planner's 3-second timeout.
